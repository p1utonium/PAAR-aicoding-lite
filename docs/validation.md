# v0.1 首轮验证记录

日期：2026-09-06。结论：实现及本机工具验证通过，**待用户业务体验验收**。真实任务效率、新手独立操作和完整 R5 集成效果未验证。

## 环境与复核方式

Windows，Node.js v26.3.0，内置 Chromium 浏览器；未安装第三方运行包。声明支持 Node.js 22+，本轮没有在 Node.js 22、macOS 或 Linux 实机复测。

在项目根目录运行：

```text
node --test tests/*.test.mjs
node scripts/paar.mjs check
node scripts/paar.mjs brief
```

## 自动化验证

30 项测试全部通过。覆盖单记录的小任务、空任务列表、重复标识、缺失与循环依赖、畸形对象、缺少验收证据、虚假完成状态、缺少用户确认记录、多任务同时执行、前置任务未验收、证据文件不存在或越界，以及新进程生成接续说明。

服务测试覆盖只读方法限制、静态资源允许清单、跨站和异常 Host 拒绝、文件损坏或缺失返回错误、记录大小上限、最新文件即时读取、HEAD 无响应体，以及读取不会新增第二个状态快照。

首次运行有 1 项 Host 测试失败：通过 fetch 设置 Host 时未得到预期拒绝结果。改用 node:http.request 明确发送请求头后得到 403；保留了原服务检查和原断言标准。最终全部通过。此证据支持检查逻辑在测试环境成立，不代表完成全面安全审计。

## 浏览器观察

在独立本机测试记录上进行了故障操作，实际项目当前记录没有被用于损坏测试。

| 操作 | 实际观察 |
|---|---|
| 打开当前任务地图 | 四个节点及依赖可见，显示 0 / 4 已验收 |
| 选择任务 | 显示正确状态、验收条件和下一步 |
| 搜索 R5 | 选中多闭环 R5 节点，详情同步 |
| 定位验证中 | 选中首轮节点，详情同步 |
| 取消选择 | 详情回到选择提示，取消和居中按钮禁用 |
| 拖动、滚轮缩放 | SVG 位移与缩放值变化，图可操作 |
| 故意写坏测试记录后刷新 | 明确提示“更新失败 · 显示上次记录”；原目标与任务保留 |
| 修复测试记录并改变目标 | 自动恢复“读取正常”，显示新目标，仍为 0 / 1 已验收 |
| 停止测试服务 | 显示更新失败并保留旧记录，没有假装实时成功 |
| 回到正式地图 | 正常加载；当前优化任务仍未被记为已验收 |

视图经过截图检查，主要区域和任务详情可读。搜索当前用于定位唯一匹配，状态定位选择首个匹配；不是高级筛选列表。未验证大规模节点布局、所有分辨率、辅助设备或所有浏览器。

## 减负结果与尚未证明的效果

本版确实取消了小任务的强制任务卡、派发、锁与队列维护，默认规则读取入口减少为一个，进度只维护一份，地图不再需要额外快照发布。这些是实现结构事实。

没有测量或声称模型 token 减少比例、耗时节约比例、返工降低比例或新手成功率。下一步由用户体验当前地图和接续方式；通过后进入真实任务减负对比。
