
没有测量或声称模型 token 减少比例、耗时节约比例、返工降低比例或新手成功率。下一步由用户体验当前地图和接续方式；通过后进入真实任务减负对比。

## 2026-09-06 补充：工程依赖与人工验收分离

本次针对旧检查要求所有前置任务 done 才能推进的问题做局部修正。业务验收尚未通过，未修改任何任务为 done，未填写验收人。

后续任务可选字段 allow_unaccepted_dependencies 引用 decisions 中唯一的已确认决定 question。省略时维持前置已验收要求；有真实授权并引用该决定时，前置内部验证通过、处于 awaiting_acceptance 即可继续工程。缺少实际证据文件仍被拒绝。该引用只表达已有授权，不具备身份认证或自然语言授权判定能力，也不扩大任务范围及发布权限。

新增 13 项测试，总计 43 / 43 通过，原有 30 项全部保留。复核命令仍为 node --test tests/*.test.mjs。新增覆盖：

- 默认继续等待业务验收，已验收前置正常放行；
- 授权后可继续，校验不修改记录，前置保持未验收；
- 空值、布尔值、不存在或重复的决定引用被拒绝；
- 待开始、阻塞、仍在验证的前置不能放行；
- 验证失败不能放行，缺少验收人不能声明 done；
- 跳到 awaiting_acceptance 或 done 不能绕过前置检查；
- HTTP 接口检查实际证据文件，允许合法继续但已验收数量仍为 0，删除授权引用后再次拒绝。

本机浏览器刷新后观察：新人入口详情显示“前置内部验证通过即可”、对应授权决定及“不代表前置已获业务验收”；未配置例外的复杂任务显示默认等待验收条件；看板保持 0 / 5 已验收。接续说明同步显示开工条件。
