# 从这里开始

这是 PAAR-aicoding-lite 的早期试用指引。你无需学习 PAAR 或 R5；先描述自己希望实现的业务。当前仍需要一个能读写本地项目的 AI 编程工具，单独打开地图不会开始开发。

## 第一次使用

要开发自己的业务，请在 AI 编程工具中打开**你的业务项目目录**，并把 PAAR-aicoding-lite 的仓库链接或本地位置提供给 AI。还没有业务目录时，说明希望放在哪里，由 AI 在获授权的位置准备；不要默认在机制源码仓库里开发业务。不要把账号密钥写进需求。

把下面这段话发给 AI，并替换最后一句业务需求：

> 请阅读 PAAR-aicoding-lite README 文末的 agent 执行指令，按“业务项目”路径工作。先检查我打开的业务项目及其已有规则、活动记录和文件改动；机制源码只作参考，不复制它的任务或验收状态。由你维护最小记录、实施和验证，我负责说明业务及确认关键取舍。缺少目录或文件访问能力时，请明确指出，不要声称已经接入。
>
> 我的需求是：……

AI 应优先复用业务项目已有活动记录及其格式；没有记录时，才按 agent 指引在业务项目内准备 work/current.json。已有规则、记录或同名文件不能被模板覆盖。v0.1 的这条路径只采用协作方法，不自动安装机制、修改项目入口或接通地图。

只有**修改 PAAR-aicoding-lite 本身**时，才打开机制源码目录，读取该目录的 AGENTS.md 和 work/current.json。它们记录机制开发，不是你的业务进度。两条路径的具体步骤统一以 [README 文末的 agent 执行指令](../README.md#给-ai-agent-的执行指令v01)为入口。

## 业务可以这样讲

“我想记录客户跟进。我要能添加客户、记录一次跟进、设置下次联系日期，并看到哪些客户需要联系。关闭后再打开，记录还在。先只给我一个人用。”

你也可以只讲最初的想法。AI 应该帮你收敛到一个可体验的结果，并只提出影响业务的必要问题。功能多不代表第一版必须全做。

## 查看进度

需要查看**机制自身的优化进度**时，Windows 中可以在机制源码目录双击 start-monitor.cmd。它会启动一个本机只读地图；需要 Node.js 22 或更高版本。遇到无法启动，把显示的错误交给执行者处理，无需自行修改系统配置。

这张地图不会自动显示你的业务项目。业务进度由 AI 根据业务项目的记录和实际文件说明；不需要为此打开机制地图。

- 待开始：还没有实施。
- 进行中或验证中：执行者正在处理。
- 已阻塞：缺少输入或遇到问题，应有下一步说明。
- 待业务验收：有内部验证记录，仍需真实体验。
- 已验收：记录了用户明确确认。

看到了地图，只能说明进度入口可见；不能证明功能已可用。

## 暂停与继续

需要暂停时，可以告诉 AI：

> 请停在可恢复的位置，记录已完成部分、未解决问题和下一步，并说明实际文件是否已经保存。

重新打开项目后，可以告诉 AI：

> 请读取现有规则和当前记录，核对实际文件后告诉我从哪里继续。已经确认的业务决定不要重复问；不确定的事情不要猜成已完成。

这两段话帮助表达意图，不会使工具获得暂停后台任务或恢复任意程序的额外能力。执行者要核实实际状态。

## 什么时候找你确认

执行者可以自行处理已授权范围内的技术工作。改变业务效果、费用、重要数据、公开发布或其他重要边界时，仍需要你的决定。

收到可体验结果后，按自己讲的业务场景尝试。如果不符合预期，直接描述“做了什么、看到了什么、希望是什么”。不用替 AI 定位代码问题。

目前正在完善首次使用入口和复杂任务验证。可以先提出体验反馈，不必为了推进开发而说“已经验收通过”。
